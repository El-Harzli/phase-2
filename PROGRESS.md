## Decisions

- JavaScript, no tests for now, Prettier, old `Dashboard` renamed to `admin`
- Keep the WebP image-variant pipeline; `scripts/` stays at the project root
- React Compiler runs only on `src/admin`; `src/shared` and `src/site` are not compiled
- Admin shell names: `AdminLayout`, `Sidebar`, `Topbar`; nav labels and page titles live together in `admin/config/navItems.js`
- Context files are exempt from the react-refresh lint rule (`eslint.config.js`); `context/` stays singular by decision
- `FullScreenSpinner` lives in `shared/` because `App.jsx` uses it while the admin chunk loads
- Section order changed after reading the old code: Conveniences, Agents, Neighborhoods, Categories, Featured, Properties, Overview
- WhatsApp card (business number + pre-filled message) dropped from the Settings form; its database columns are untouched. Revisit once the whole site is done
- Deliberate changes from the old Settings behavior: prices must be whole numbers; latitude/longitude must be plain decimals; the phone number field accepts digits only while typing; number inputs block `e`, `+` (and `-`, `.` for prices)
- All errors are red (forms, Login box, error toast)
- Double-submit fixed for every modal form through the shared `ModalForm` ("Saving…", Cancel and Save disabled while saving), and for the fade-out window through `PresenceLayer`
- Settings keeps its own conflict message permanently (a single row that can't be deleted); every other section uses `updateWithConcurrencyCheck` (including `updateProperty`, whose old messages were word for word the same)
- `handleSaveError` has a `closeOnConflict` option for tiny inline edits (renaming a sub-type closes on conflict; bigger forms stay open)
- `PropertiesContext` is fully ported: read, featured order, delete (with photo cleanup after the database delete), add, update, images and amenity links
- New data contexts have no manual `useMemo` lists; the compiler memoizes the value
- Deleting a row that another admin already deleted shows "deleted" (intentional); editing one shows the "no longer exists" error
- Manual tests that write to the database use unchanged values, or a throwaway record created and deleted in the same test
- Saving a property sends the whole form every time (every column, the full photo list and the full amenity list), never only the changed fields; stale-form overwrites are stopped by the `updated_at` check, so a diff-only save wasn't worth the extra logic. Photo files are only uploaded when newly chosen
- Image pipeline: dropped the legacy `VITE_SUPABASE_IMAGE_TRANSFORMS` fallback and the unused single-file `uploadFile` export; `uploadFile.js` became `admin/api/imageStorage.js`; `heic2any` installed (loads only for HEIC uploads); avatars get no resized copies; `leaflet` and `react-leaflet` installed for the map
- Lint: `no-unused-vars` ignores rest siblings; every targeted `eslint-disable` line carries a comment explaining why
- Reorderable lists (Neighborhoods, Featured): persist on drop only; skip the save when the order didn't change; put the list back if the save fails
- Neighborhoods: new rows get the highest position + 1; the photo field is `PhotoUpload` (was `ImageUpload`) and shares preview cleanup with `AvatarUpload` through `useLocalImageCleanup`, which takes a list of URLs
- State that mirrors a prop is synced during render with a "previous value" check, not in an effect; for derived lists the check compares the list of ids, not the array
- Categories: a sub-type used by listings can't be deleted (so the old "unassign from properties first" step was removed and never ported); if a new category's amenity step fails after the category was created, a specific message shows and the form closes (no duplicate on retry); Enter in a sub-type field no longer submits the category form
- Featured: the page uses `PageHeader` (one `h1` per page, from the top bar); admin price formatting lives in `admin/lib/formatPrice.js`; thumbnails keep loading the original photos
- Property form: price, beds, baths, area, garage, year built and the coordinates are text boxes (numeric keypad on phones) checked with strict patterns, because a browser number box reports an unreadable paste (like `5e`) as empty and an optional field would save as 0.
